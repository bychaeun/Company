# CHAE EUN.ZIP — 채은 지식 저장소

Sites 정적 화면 + Google Apps Script + 비공개 Google Sheets/Drive 구조입니다.
Render나 서비스 계정은 필요하지 않습니다.

현재는 코드 업로드 단계이며 실제 사이트 배포 및 Google OAuth/권한 연결은 미완료입니다.
아래 설정을 완료한 뒤 실서비스 로그인과 승인 흐름을 검증해야 합니다.

## 구성
- dist: 공개 가능한 화면/푸딩/스크립트만 포함. 메모와 사용자 목록은 포함하지 않습니다.
- apps-script: 시트에 연결된 Apps Script 편집기에 등록할 서버 코드.
- Google 로그인 → 접근관리 시트 대기 등록 → 관리자 승인 → 자료 조회.
- 메모와 이미지 요청마다 서버에서 세션과 시트 승인상태를 다시 검사합니다.
- Google ID를 기준으로 사용자 식별. 관리자 이메일은 Script Properties에서 설정하고 최초 검증한 ID에 연결합니다.
- 앱이 열려 있는 동안 30분마다 갱신. 수동 동기화는 즉시 시트를 읽습니다.
- 웹앱 설치, 제목/내용 검색, 동적 대분류/소분류, 메모 PNG 저장을 지원합니다.

## 설정
1. COMPANY 시트에 연결된 Apps Script에 apps-script/Api.gs를 추가합니다. 기존 onEdit는 유지합니다.
2. appsscript.json의 권한을 적용합니다. 메모 시트는 비공개로 두고 편집자에게만 공유합니다.
3. 스크립트 속성 GOOGLE_CLIENT_ID와 ADMIN_EMAILS(쉼표 구분)를 설정합니다. 필요하면 SPREADSHEET_ID도 설정합니다.
4. Google OAuth 웹 클라이언트의 승인된 JavaScript 원본에 실제 사이트 원본을 추가합니다. 비밀 키는 브라우저에 넣지 않습니다.
5. setupChaeZip 실행으로 접근관리 탭을 준비하고 Google 권한을 승인합니다.
6. Apps Script 웹앱을 본인으로 실행하도록 배포합니다. 외부 요청을 받는 엔드포인트여도 메모는 인증 없이는 반환하지 않습니다. 배포 권한 변경은 소유자가 검토해야 합니다.
7. dist/config.js의 /exec URL을 실제 배포와 맞춥니다. 편집기 저장만으로 기존 배포 버전이 바뀌지는 않습니다.
8. 관리자 로그인, 대기 계정 거절, 승인, 시트에서 차단, 비공개 이미지 표시를 실서비스에서 확인합니다.

## 접근관리
Google ID | 이메일 | 이름 | 승인상태 | 최초 로그인 | 최근 로그인

승인상태는 대기 / 승인 / 거절 / 차단입니다. 헤더와 Google ID는 수정하지 마세요.
웹 관리자 화면의 변경도 같은 시트에 기록됩니다. 관리자 계정은 서버 설정이 우선입니다.
시트를 편집할 수 있는 사람은 접근권한도 변경할 수 있으므로 신뢰하는 관리자만 편집해야 합니다.

## 비공개 이미지
이미지 셀에 비공개 Drive 파일 링크를 넣습니다. 여러 장은 |로 구분합니다.
Apps Script 실행 계정이 읽을 수 있는 PNG/JPEG/WebP/GIF, 4MB 이하 파일만 지원합니다.
승인된 사용자가 요청한 경우에만 서버가 읽어 보내며 공개 URL로 바꾸지 않습니다.
이전 공개 이미지 링크의 공유 설정까지 자동 변경하지는 않습니다.

## 제한과 보안
- 세션은 브라우저 탭의 sessionStorage에 저장되고 서버에서 8시간 후 만료됩니다. 로그아웃 시 서버 세션도 폐기합니다.
- 차단 후 다음 서버 요청부터 거절됩니다. 열린 화면은 최대 1분 후 지워지며 이미 캡처/저장한 내용은 회수 불가입니다.
- 로그인 시 Google tokeninfo 검증을 사용합니다. 검증 서비스 오류/제한 시 로그인을 거절하며 검증 없는 우회는 없습니다. Google은 대규모 운영에는 검증 라이브러리 사용을 권장하므로 사용량 확대 시 인증 구조 재검토가 필요합니다.
- Apps Script의 외부요청·실행시간·동시실행·속성 저장 한도가 적용됩니다. 쿼터는 방문자 수가 아니며 Google 정책에 따라 변합니다.
- 새 Sites 배포는 소유자 전용입니다. 다른 사람의 Google 승인만으로 Sites 자체의 열람 제한이 해제되지는 않으므로, 외부 사용자 초대 전 Sites 접근정책도 검토해야 합니다.

실제 OAuth 원본 등록, Script Properties, 권한 승인, Apps Script 새 버전 배포가 끝나야 실제 로그인할 수 있습니다.
