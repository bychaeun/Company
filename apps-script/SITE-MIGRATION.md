# 내 스펙관리 통합 적용

운영 Apps Script 업데이트 및 아래 통합 실행이 완료되기 전에는 시트나 열을 삭제하지 않습니다. GitHub Pages 배포만으로 Apps Script 서버는 업데이트되지 않습니다.

1. 기존 Apps Script 프로젝트의 `Api.gs`, `SpecRegistry.gs`, `Specs.gs`, `Code.gs`를 이 저장소의 같은 파일 내용으로 저장합니다. 비공개 Script Properties와 기존 웹앱 배포 ID는 유지합니다.
2. `migrateUnifiedSites`를 실행합니다. `내 스펙관리`를 유지하고 필요한 항목만 빈 열 뒤에 추가합니다. 기존 ID, 주소, 건설사, 사진, 좌표와 사용자 추가 열은 유지합니다. `현장별 관리`의 활성 내역이 있으면 이전하고, 읽어서 이전을 확인한 후 원본 탭을 숨깁니다. 원본은 삭제하지 않습니다. 반복 실행해도 같은 원본 ID를 재복사하지 않습니다.
3. 실행 로그에서 `내 스펙관리로 통합 완료`를 확인합니다. `내 스펙관리`에 원래 현장과 건설사, 주소, 좌표, 사진이 남아 있는지 확인합니다.
4. 기존 웹앱 배포를 새 버전으로 갱신합니다. 실행 사용자, 접근 범위, 웹앱 URL은 변경하지 않습니다.
5. 앱의 지도와 현장 목록에서 같은 현장이 보이는지 확인합니다. 번호 조회·수정·자동완성, 사진 URL과 여러 스펙·경면 저장을 확인합니다.

이후 `스펙번호 관리`의 `경면` 열은 삭제해도 됩니다. 필수 항목은 `종이넘버`, `스펙넘버`, `비고`입니다. `관리 ID`, 수정일, 삭제일 등 내부 관리 열은 유지합니다.

열은 첫 행의 제목으로 찾으므로 위치를 바꿀 수 있습니다. 제목은 중복되지 않아야 합니다. `건설사`, `건설사 이름`, `건설사명`은 같은 항목으로 인식하며 이 중 하나만 사용합니다. 기존 `M/H 오픈날`, `완공 연월`도 그대로 사용할 수 있습니다.
